# Contributing Guide

Thank you for your interest in contributing to this project. I welcome contributions from the community that align with
the library's goals and purpose.

## Before Contributing

1. Please first open an issue on GitHub before submitting any pull requests. This helps us to:
    - Discuss the proposed changes
    - Ensure the change aligns with the project's goals
    - Avoid duplicate work
    - Provide guidance and feedback early in the process

## Contribution Process

1. **Create an Issue**
    - Start by creating a new issue describing:
        - The problem you're trying to solve
        - The value proposition of your proposed changes
        - Any potential impacts on existing functionality
    - Wait for maintainer feedback before proceeding

2. **Fork & Create Branch**
    - Fork the repository
    - Create a branch with a descriptive name (e.g., `feature/new-validator` or `fix/error-handling`)

3. **Development Guidelines**
    - Write clear, documented code
    - Include tests for new functionality
    - Follow the existing code style and conventions
    - Keep changes focused and atomic

4. **Submit Pull Request**
    - Ensure your PR references the original issue
    - Provide a clear description of the changes
    - Include any necessary documentation updates
    - Make sure all tests pass
    - Keep your PR up-to-date with the masterßß branch

## Code Review

- All contributions will go through a code review process
- Be open to feedback and be responsive to comments
- Maintainers may request changes before merging
